# Bynálix

本地優先的個人健康分析平台。
Bynálix 的設計目標是長期自我觀察，而非參與度優化。
追蹤、觀察並分析自己的長期行為數據 — 不依賴不透明的雲端服務或黑箱 AI 系統。

---
## 哲學

Bynálix 並不是為了提供答案告訴使用者如何生活，而是讓使用者自己看見答案。

它幫助使用者：
- 記錄長期個人數據
- 觀察行為模式
- 探索相關性
- 了解哪些因素真正影響自己

目標不是盲目優化，
而是透過自有數據進行更深入的自我理解。

## 功能

### 記錄
- **飲食** — 從可搜尋的食物庫組成餐點，支援自訂餐別、可重複使用的餐點範本與「我的最愛餐」；自訂食物編輯器以「基準量 + 單位」（預設 100 g）記錄營養素，任何份量都由此換算，以 ml 記錄的飲品還可自動計入當日飲水；分類與聚合標籤篩選（澱粉／蛋白質／油質／我的最愛），並支援分頁
- **運動** — 重訓以「部位 × 組數 × 次數 × 重量」記錄；有氧支援區間式訓練（跑步、游泳、自行車），含距離、時長與配速；其他活動以時長與強度記錄。熱量消耗在已知體脂時以去脂體重估算，否則以體重估算
- **身體** — 體重、體脂率、骨骼肌總量與分部位分佈、身體水分、內臟脂肪等級、腰圍
- **睡眠** — 時長、品質與備註，Android 可依螢幕活動自動偵測整夜的睡眠區間
- **飲水** — 每日攝取量對照飲水目標

### 目標
- 八種模式 — 三段減脂速度、三段增肌速度、維持體重，以及完全自訂
- 熱量與三大營養素目標由 BMR、NEAT、TDEE 推導（Mifflin-St Jeor；已知體脂時改用 Katch-McArdle）。去脂體重取自實際量測的體脂數值後固定保存，不會隨每日體重漂移
- 自訂模式可再指定任意目標指標 —— 重訓、有氧、身體、飲食或運動消耗任一項 —— 並針對它評分最多五個變因

### 分析
- **歷史** — 任意區間內的體重、熱量、三大營養素、飲水、睡眠、重訓量、單項最大重量、運動分布、活動消耗與身體組成，可選擇疊加趨勢擬合線與每週斜率
- **相關性** — 針對目標的影響因子排名，以及以「日對日變化」建立的變因關係網絡（Spearman），含 0–3 天的延遲搜尋，避免共同趨勢製造出假關聯
- **規律** — 經顯著性檢定的「週末 vs 平日」效應；以及關係變化，用來區分「一直都成立」與「記錄中途才真的開始」的關聯
- **穩定度** — 七角星圖，評估體重、熱量、三大營養素、飲水、睡眠各自的日對日波動有多小，且不受長期趨勢影響
- 每個結果都附上樣本數與資料密度；資料不足時會明說「資料不足」，而不是給一個撐不住的數字

### 輸出
- 任一張圖表都可以存成圖片，並壓上輸出日期
- 全表格加密 CSV 匯出（AES-256 ZIP）
- 完整資料庫匯出與匯入，用於備份或轉移到其他裝置

### 隱私與平台
- 本地優先 —— SQLite 存在自己的裝置上。不需帳號、沒有伺服器、沒有遙測
- 完全離線可用
- App 啟動上鎖（密碼），Android 另支援生物辨識解鎖
- Android、Windows、macOS，以及可側載的未簽章 iOS 版本
- 全介面支援 English 與繁體中文

## Bynálix 為何存在

Bynálix 的誕生是為了幫助使用者使用自己的長期數據驗證想法，
而不是完全依賴一般化的網路建議。

---
## 相關性分析

相關性並不代表因果關係。
Bynálix 提供探索式分析，旨在幫助使用者觀察可能的長期行為模式。

---
## 隱私與資料所有權

- 不需要雲端帳號
- 不收集使用者資料
- 不顯示廣告
- 你的資料屬於你自己
- 可選的 App 鎖定（PIN / 生物辨識）
- 支援 SQLite 資料庫匯出
- 支援本地備份與還原

## 技術架構

- **前端**：React 18 + TypeScript + Tailwind CSS + Vite
- **後端**：Tauri v2（Rust）
- **資料庫**：SQLite（`@tauri-apps/plugin-sql`）
- **平台偵測**：`src/lib/platform.ts`
- **國際化**：`src/lib/i18n.ts`

## 路線圖

Bynálix 的發展重點將持續圍繞「本地優先與長期自我觀察」。

短期：
- UI 與效能優化
- 核心資料流與穩定性提升

中期：
- 強化視覺化與互動體驗

長期：
- 更完整的個人資料匯出與遷移能力
- 多語言與跨平台體驗優化
- 資料庫靜態加密（SQLCipher，金鑰由 PIN / 生物辨識衍生）
